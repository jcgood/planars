## 2. The fixes

### Fix 1: catalogue entry for the boundary-strength test

`plot_boundary_strength_test()` is the only chart function with no section
in `docs/planarsviz_charts.md`, though the renderer draws 18 charts from it.

**Add section `## 17. Boundary-strength test`** after §16 (arbitrary
layers), and a `[Boundary-strength test](#17-boundary-strength-test) ·`
link in the Contents line before `[Name changes]`. Follow §14–§16's shape:
what it shows, image, calls, options table, canvas, bundle requirement,
renderer-name table, one note on references.

Facts to use (from `r/planarsviz/R/boundary_strength_test.R` and
`scripts/INDEX.md`):

- **What it asks:** is a position's boundary strength (chart 12's summed
  strength) — and especially its *jump* from the previous position — higher
  than the same spans placed at random would give? It reuses
  `span_placement_test.py`'s null: each span keeps its length, position is
  randomized over the whole structure. The direct test of the "clear jump at
  the left edge of the orthographic word" reading of chart 12.
- **What it draws:** for one group, two stacked panels, left edge on top and
  right edge below. At each position: the real value (line and points)
  against the null's 5th–95th percentile band (ribbon) and mean (dashed).
  Points with `p_value_ge_observed` below `alpha` are filled, the rest open,
  so a run of filled points stands out from noise.
- **Calls:**
  ```r
  plot_boundary_strength_test(bundle)                          # pooled, jump
  plot_boundary_strength_test(bundle, statistic = "level")
  plot_boundary_strength_test(bundle, group = "tonosegmental")
  ```
- **Options:** `group` (`"all"`, the default — pooled — or a domain type, or
  a bundle name), `statistic` (`"jump"`, the default: strength at p minus
  strength at p−1; or `"level"`: the strength itself), `alpha` (default
  0.05), `line_colour`.
- **Canvas:** 11 × 7 in. Folder: `boundaries`.
- **Needs** a bundle exported with `--boundary-strength-test-permutations`
  (5000 to match the committed files). Say what the function does without
  it — check the R code for its exact stop message rather than assuming it
  matches the fragmentation chart's.
- **Renderer names:** `boundary_strength_test_jump_<group>` and
  `boundary_strength_test_level_<group>`, one pair per group in the table.
  For nyan1308 that is nine groups — `all`, the five domain types,
  `syntaxlike`, `syntaxlike_notono`, `phonologylike` — so 18 files. List the
  pattern, not all 18 rows. Old file: none.
- **References:** like §16, no reference image: it was written in the
  package from the start (INDEX.md: "no earlier script to port or reference
  image to freeze"). Say what it *is* checked against — confirm which test
  covers `boundary_strength_test.tsv` (look in `tests/test_planarsviz_bundle.py`
  and `scripts/planarsviz_checks/`) and name it; if none does, say so
  plainly rather than implying a check exists.

**Image:** `docs/planarsviz_charts/boundary_strength_test_jump_all.png`.
Render it, don't copy it by hand:

```sh
Rscript scripts/render_planarsviz.R --bundle results/planarsviz/nyan1308 \
    --plots boundary_strength_test_jump_all --formats png \
    --output <scratch folder>
```

then copy the PNG from `<scratch folder>/boundaries/` into
`docs/planarsviz_charts/`. Do not render into `results/`; that would rewrite
the manifest for a documentation change.

### Fix 2: `results/visualizations.md` entry for the same charts

The 18 PDFs in `results/nyan1308/boundaries/` named
`nyan1308_boundary_strength_test_{jump,level}_<group>.pdf`, and
`nyan1308_boundary_strength_test.tsv`, appear nowhere in this file — not in
a section of their own and not in the "Charts covered only by the catalogue"
table. The other three permutation tests each have a section.

**Add a section after "Is the family count remarkable for that many
arbitrary spans?"** (the arbitrary-layers section, currently ending just
before "How much tree structure each family leaves open"), in the same
shape as the span-placement and arbitrary-layers sections:

- Heading: a question, like its neighbours — e.g. *"Is the jump in boundary
  strength more than chance?"* — then
  `### nyan1308_boundary_strength_test_jump_<group>.pdf / _level_<group>.pdf / nyan1308_boundary_strength_test.tsv`.
- What it tests (as Fix 1), and the p-value direction:
  `p_value_ge_observed`, small = more strength than chance — the mirror of
  the other tests' `p_value_le_observed`. State this explicitly; it is the
  one test whose small p-value means "more", not "fewer".
- What each file holds. The TSV: one row per (group, side, statistic,
  position) with `observed`, `null_mean`, `null_p05`, `null_p95`,
  `p_value_ge_observed`, `n_permutations`, `seed`; no per-draw table, only
  percentiles, because the chart draws a band.
- Findings, copied from `scripts/INDEX.md` and re-checked against the
  committed TSV before being written: pooled left-edge jump at position 5,
  p = 0.0010; best right-edge position 21 (jump), p = 0.0522; tonosegmental
  right edge at 17, p = 0.0004, the strongest of any group. If a number in
  the TSV disagrees with INDEX.md, the TSV wins and INDEX.md gets fixed too.
- How to regenerate: `python scripts/analysis/boundary_strength_test.py`
  (the TSV; 5000 draws, seed 0) and the charts through the renderer from a
  bundle exported with `--boundary-strength-test-permutations 5000`.
